# 다국어(영어) 대응 계획

세모반 앱의 영어 지원을 위한 작업 계획 문서. 기본 언어는 한국어(`values/`)를 유지하고 영어는 `values-en/`으로 추가한다.

## 현황 (2026-07-09)

- `values-en` 없음. 문자열 리소스 95개(`values/strings-*.xml`, feature별 분리)
- Kotlin 코드에 한글 하드코딩 약 443줄 — Compose 전환 화면들이 텍스트를 코드에 직접 보유
- 레이아웃 XML 하드코딩 25건 (남은 View 기반 화면)

| ④ | 서버 데이터 영어 대응 — 백엔드 협의 필요 (아래 참고) | |

## 추출 규칙 (①)

- Compose에서는 `stringResource(R.string.key)`, 포맷 인자는 `%1$s`/`%1$d` 플레이스홀더
- 키 네이밍은 기존 관례대로 `<feature>_<desc>`, 파일은 `values/strings-<feature>.xml`
- 한글이 포함된 문자열만 추출 대상. `"$weight kg"` 같은 숫자·단위 조합은 제외
- `@Preview` 내 더미 데이터("몽실이" 등)와 `Log` 메시지는 추출하지 않는다
- `contentDescription`도 접근성 번역 대상이므로 리소스화
- `CustomSnackBar` 메시지를 `Constants.kt` 상수로 두는 기존 관례는 리소스 참조로 대체한다 (완료 후 CLAUDE.md 갱신 필요)
- 이미 있는 키(`all_*`, `petadd_*` 등)는 재사용

## ② 번역 결정사항

- 파일 구조: `values-en/`에 `values/`와 동일한 feature별 파일. 값이 로케일 무관인 키(`push_notification_channel_*`, `medicalrecord_*_length` 등)는 기본 파일에 `translatable="false"` 지정 후 번역 제외
- 톤: 한국어의 해요체에 맞춰 캐주얼한 영어("Poop"/"Pee", "Girl"/"Boy", "Something went wrong.")
- 브랜드: `app_name` → "Semoban". `onboarding_complete_subtitle`의 "멍케어"(구 앱명 잔재)도 "Semoban"으로 번역
- 반려견 이름 뒤 "님" → 영어는 소유격(`%1$s\'s ...`)
- 체중 차트 축(DecimalFormat 패턴): 주 `\'W\'#`("W3"), 월은 숫자만 `#`, 12월 리터럴은 "12"
- 생일 피커 년/월/일 포맷(`all_year_format` 등): 영어는 접미사 없이 `%1$d`
- 요일 약어(`cdrp_*`): `awesome-calendar` 라이브러리의 요일 헤더 리소스를 앱이 같은 키로 덮어쓴 것(앱 코드에서는 미참조). 영어는 라이브러리 원본 기본값과 동일한 3글자(Mon~Sun)로 복원
- 주의: ③ 전까지 코드 생성 날짜 문자열("yyyy년 MM월 dd일", 오전/오후)은 영어 기기에서도 한국어로 표시됨

## ③ 날짜 포맷 구현

- 표시용 패턴을 `strings-datetime.xml`(ko) / `values-en/strings-datetime.xml`(en) 리소스로 정의: 날짜 3종(`yyyy년 MM월 dd일`↔`MMM dd, yyyy` 등)과 12시간제 2종(`a hh:mm`↔`hh:mm a` 등)
- 루트 `LocaleDateTimeFormats` 오브젝트가 리소스에서 패턴을 읽어 `DateTimeFormatter`를 생성. 콜사이트가 Fragment·Composable·ViewModel에 20곳 이상이라 Context 스레딩 대신 `GlobalApplication.applicationContext()`를 사용(표시 전용이므로 허용, 구형 패턴 주의사항과 별개)
- 교체된 utils: Excreta·Feed·Symptom·Notice·DogAddOnBoarding(날짜), MedicalRecordUtils/MedicalRecordDateUtils/MedicalRecordFormScreen·Supplement·Excreta(12시간제). `오전`/`오후` 수동 조합은 전부 `a` 패턴 렌더링으로 대체 — `ExcretaConstants`의 `NOON`/`MORNING`/`AFTERNOON`/`TIME_FORM` 상수 삭제
- `SupplementUtils`의 "시간 형식 오류" 폴백은 `datetime_time_error` 리소스로 이관
- `BirthdayBottomSheetFragment` 연도 목록을 하드코딩 배열(2024 고정, 2000~2009 누락) → `LocalDate.now().year downTo 1990` 자동 생성으로 교체. 기본 선택은 최신 연도
- 서버 통신용 포맷(`yyyy-MM-dd`, `HH:mm:ss` 등)은 로케일 무관이므로 변경하지 않음
- 한국어 출력은 기존과 동일(패딩 포함 검증), 영어는 `Jan 05, 2026` / `08:30 AM` 형태

## 앱별 언어 설정 (localeConfig)

- `res/xml/locales_config.xml`(ko, en) + 매니페스트 `android:localeConfig` 선언 (2026-07-22)
- Android 13+ 시스템 설정 > 앱 > 세모반 > 언어에서 한국어/영어 직접 선택 가능. 선택값 저장·적용은 OS가 처리

## 발견된 잡 이슈

- `strings-all.xml`의 `all_delete` 값 오타 "식제" → "삭제" (①에서 수정)
- 클릭 람다 등 비컴포저블 컨텍스트에서 문자열이 필요한 경우: 상태를 `R.string` 리소스 ID(`Int?`)로 들고 있다가 표시하는 컴포저블에서 `stringResource(id)`로 변환 (feed에서 확립한 패턴)
- "필수 입력 값입니다."(마침표 포함) 변형은 기존 `designsystem_required_input`(마침표 없음)으로 통일한다 — symptom에서 적용, medicalRecord·supplement 차례에 동일 적용
- `feed_required_input_description`은 `all_required_input_description`과 값이 중복 — feed 재정리 시 all 키로 통합
- `feed_image_hint`는 `all_attach_photo_hint`와 값이 중복 — feed 재정리 시 all 키로 통합
- 브랜드명/제품명 라벨·힌트가 feed(`feed_brand_label` 등)와 supplement(`supplement_brand_label` 등)에 중복 — ② 번역 시 값만 맞추면 되므로 통합은 선택
- `onboarding_direct_input`은 `feed_direct_input`과 값("직접 입력하기") 중복 — 통합 후보
- `profile_share_coming_soon`은 진료기록 공유 다이얼로그와 값이 동일해 `all_coming_soon`으로 승격 (①에서 처리)
- `BirthdayBottomSheetFragment` 기존 코드는 "yyyy-MM-dd"의 leading zero("07월") 탓에 `indexOf`가 -1을 반환해 10월 미만 월/일 선택값이 1월/1일로 초기화되는 버그가 있었음 — Int 비교로 전환하며 함께 해결 (①에서 처리)
