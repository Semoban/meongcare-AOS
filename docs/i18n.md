# 다국어(영어) 대응 계획

세모반 앱의 영어 지원을 위한 작업 계획 문서. 기본 언어는 한국어(`values/`)를 유지하고 영어는 `values-en/`으로 추가한다.

## 현황 (2026-07-09)

- `values-en` 없음. 문자열 리소스 95개(`values/strings-*.xml`, feature별 분리)
- Kotlin 코드에 한글 하드코딩 약 443줄 — Compose 전환 화면들이 텍스트를 코드에 직접 보유
- 레이아웃 XML 하드코딩 25건 (남은 View 기반 화면)

## 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| ① | 하드코딩 문자열 → 리소스 추출 (동작 변화 없음, feature 단위 진행) | 진행 중 |
| ② | `values-en/` 영어 번역 추가 | |
| ③ | 날짜 포맷 로케일 대응 — "MM월 dd일" 등 한국어 포함 패턴을 로케일별 리소스/스켈레톤으로 교체 | |
| ④ | 서버 데이터 영어 대응 — 백엔드 협의 필요 (아래 참고) | |

## 추출 규칙 (①)

- Compose에서는 `stringResource(R.string.key)`, 포맷 인자는 `%1$s`/`%1$d` 플레이스홀더
- 키 네이밍은 기존 관례대로 `<feature>_<desc>`, 파일은 `values/strings-<feature>.xml`
- 한글이 포함된 문자열만 추출 대상. `"$weight kg"` 같은 숫자·단위 조합은 제외
- `@Preview` 내 더미 데이터("몽실이" 등)와 `Log` 메시지는 추출하지 않는다
- `contentDescription`도 접근성 번역 대상이므로 리소스화
- `CustomSnackBar` 메시지를 `Constants.kt` 상수로 두는 기존 관례는 리소스 참조로 대체한다 (완료 후 CLAUDE.md 갱신 필요)
- 이미 있는 키(`all_*`, `petadd_*` 등)는 재사용

## 서버 의존 항목 (클라이언트 범위 밖, 백엔드 협의)

- 품종 목록 (온보딩/반려견 등록 검색)
- 이상증상 종류 문자열 (`symptomString` — 클라이언트가 문자열 매칭으로 아이콘 분기 중이라 서버 변경 시 `SymptomType` 매핑도 수정 필요)
- 공지사항/이벤트 콘텐츠, FCM 푸시 알림 문구
- 에러 응답 메시지

## 발견된 잡 이슈

- `strings-all.xml`의 `all_delete` 값 오타 "식제" → "삭제" (①에서 수정)
- 클릭 람다 등 비컴포저블 컨텍스트에서 문자열이 필요한 경우: 상태를 `R.string` 리소스 ID(`Int?`)로 들고 있다가 표시하는 컴포저블에서 `stringResource(id)`로 변환 (feed에서 확립한 패턴)
- "필수 입력 값입니다."(마침표 포함) 변형은 기존 `designsystem_required_input`(마침표 없음)으로 통일한다 — symptom에서 적용, medicalRecord·supplement 차례에 동일 적용
- `feed_required_input_description`은 `all_required_input_description`과 값이 중복 — feed 재정리 시 all 키로 통합
- `feed_image_hint`는 `all_attach_photo_hint`와 값이 중복 — feed 재정리 시 all 키로 통합
- 브랜드명/제품명 라벨·힌트가 feed(`feed_brand_label` 등)와 supplement(`supplement_brand_label` 등)에 중복 — ② 번역 시 값만 맞추면 되므로 통합은 선택
- `onboarding_direct_input`은 `feed_direct_input`과 값("직접 입력하기") 중복 — 통합 후보
